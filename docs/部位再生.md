# v0.14 部位再生实验

本次实现的是逐部位开启游戏原生再生，并给每个部位独立的选择开关。它提供了测试“已毁部位能否由游戏自行恢复”的路径；尚未证明脱落模型、碰撞或武器功能会恢复。

## 字段依据

来源：[filediver 的 HealthComponent / DamageableZoneInfo](https://github.com/xypwn/filediver/blob/master/datalibrary/health_component.go)。从脚本已有的运行时锚点 `Health=+0xE8`、`ZoneName=+0x60`、部位步长 `0x228`，按字段顺序推导：

| 部位记录内偏移 | 字段 |
|---|---|
| `+0xE8` / `+0xEC` | Health / Constitution |
| `+0xF0..+0xF4` | Immortal 和四个下倒/死亡标志 |
| `+0xF8` | AffectsMainHealth |
| `+0xFC..+0x13B` | ChildZones[16] |
| `+0x13C` / `+0x13D` | KillChildrenOnDeath / RegenerationEnabled |
| `+0x13E` / `+0x13F` | BleedoutEnabled / AffectedByExplosions |
| `+0xA8` | OnHealScriptEvent（只读诊断） |
| `+0x148` | OnDeadDisableAllActors（只读诊断） |

完整地址是 `配置地址 + 0x208 + 部位索引 × 0x228 + 0x13D`，不是 Health 运行时血量记录的偏移。脚本不会仅凭一个 0/1 字节就写入；会检查名称、上限、邻近布尔值、浮点范围和 ChildZones 是否引用同一配置内的部位。检查失败的部位单独跳过，并记录原因。

这些检查能拒绝明显不匹配的配置，不能替代当前游戏版本中的语义验证。全零的未知字段也可能通过形状检查。其他 `native_zone` 偏移不会自动猜测或写入。

## 开启和逐部位选择

更新 mod 包后，在设置文件中确认：

```ini
heal=native
native_zone=0x13d
part_regen=1
```

把 `reload` 写进命令文件。旧配置中已有的 `native_zone=0` 会继续生效，需要改掉这一行。

`part_regen=1` 默认选择所有有效部位。发 `parts` 后从日志复制对应的 `16位资源hash:8位部位hash`：

```ini
# 示例：禁用这个车型的一个部位，其他部位仍启用
part=35dbf54f016f3624:ca47a7a9=0
```

也可以 `part_regen=0`，只用若干 `part=...=1` 开启选中的部位。每条设置只作用于指定车型的该 hash；支持索引 0..37。禁用部位也不会经由旧的 HP 回填路径被维修。每秒点数来自该车型主血量上限 × `exo_heal` / `tank_heal` / `frv_heal`，各部位如何使用这一组件速率由游戏决定。

罩子内开启原生再生后，mod 不再直接改这些部位的 HP 或损坏位，以便观察游戏自己的再生和回血事件。离开罩子、罩子消失、`off`、切换回血方式或 `reload` 时恢复原值；恢复地址保存在写入记录里，不取新的设置偏移。只恢复仍等于本 mod 写入值、且部位名字没变的字段；写回失败每秒重试。

## 怎么判断已毁部位是否真的恢复

1. 保持载具车体存活，打坏一个可见部位；进罩子前发 `parts`，记录该部位的 HP 和外观。先在已毁之后首次开启，再对照“先开启、后损坏”的情况。
2. 进入罩子，等过 `cooldown`，发 `parts`、`hptrace 20`。日志应显示对应部位 `regen=1`；若有 `layout=...` / `native zone skip`，说明没有开启成功。
3. 分别观察 HP 是否由游戏上涨、模型是否重新出现、碰撞/移动/武器是否恢复。`regen=1` 或 HP 回满都不能单独算作部件重建成功。
4. 再打同一部位，确认回血不会被旧血量覆盖，损伤仍能正常发生。离开罩子后发 `parts`，核对开关恢复原值。

如果 HP≤0 一直不涨，说明当前引擎可能不给死亡部位执行普通再生。如果 HP 涨但模型不回来，说明还缺恢复可见性、actor、附着关系或重建实体的引擎流程。`OnHealScriptEvent` 提供一个线索，但现有资料没有给出可靠的调用/重建接口，本次不猜函数或强制重放死亡/回血事件。

已死亡/已移除的独立手臂实体仍不会复活；车体主血量≤0也不复活。配置按资源共享：同一车型只要有一辆本机有权威的载具在罩子里，同型号的其他载具也可能原生回血。这与 v0.13 的共享配置限制相同。

需要退回旧行为时用 `native_zone=0` 并发 `reload`。旧 `revive` / `tires` 只回填数据与有限的损坏位，不等于部件重新生成。

## 离线验证范围

`tests/part_regen_test.py` 用 LuaJIT 执行实际打包脚本，模拟配置/组件内存，验证 38 个部位、独立开关、原值恢复、偏移变更、配置异常、权限/死亡过滤、写失败重试、恢复失败重试和外部修改保护。测试不模拟引擎的模型或物理系统，不构成游戏内恢复成功的证据。
