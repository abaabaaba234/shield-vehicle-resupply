# 为什么以前会卡一下（以及现在怎么处理的）

## 一句话
为了让护盾里修好的血不会被下一次伤害“吃掉”，mod 要在游戏内存里找到游戏**另存的一份血量**。
这份拷贝的位置每局、每辆载具都不一样，只能靠扫描内存去找。v0.12c ~ v0.12f 是一口气扫完的，
大约 5 GB，要 4~5 秒，扫的时候游戏这一帧就停住了，所以每辆载具第一次回血时会卡一下。
v0.12g 起把扫描拆到很多帧里做，v0.12h 起控制在 15 秒左右扫完，**不再卡顿**。

## 为什么需要扫描

### 问题：修好的血挨一下就没了
mod 回血的方式是改 Health 组件记录里的血量（主血量 `+0x14`、部位血量 `+0xF8 + 4×i`）。
但实测发现，游戏扣血时**不是从记录里的当前值往下减**，而是：

```
受伤后的血量 = 游戏自己另存的“上次受伤后”的血量 − 伤害
```

例如机甲：1543 → 在护盾里修到 1800 → 挨一下变成 1444（= 1543 − 99）。
mod 加的 257 点只写进了记录，游戏那份拷贝还是 1543，一挨打就用它算，修的血全丢了。
部位血量也一样（451 → 修到 550 → 挨一下 352）。

### 为什么不能直接写那份拷贝
- 它**不在** Health 记录里，也不在记录附近的固定偏移上。filediver 的 datalibrary
  只有 HealthComponent 的配置（上限、回复速度），没有运行时这份拷贝的布局。
- 它在堆内存里，地址每局都变，每辆载具各有一份（主血量一份，部位数组一份）。
- mod 只能读写内存，拿不到游戏内部的指针链，所以没有“固定地址 + 偏移”可用。

### 所以只能像 Cheat Engine 那样找
1. **第一次扫描**：载具第一次在护盾里回血时，扫描游戏进程里所有可读写的私有内存
   （`MEM_PRIVATE` + `PAGE_READWRITE`，大约 5 GB），记下所有“等于修前血量”的地址，
   同时找“连续 N 个值 = 各部位修前血量”的整段部位数组。
2. **过滤**：之后每挨一下打，只留下跟着变成新血量的地址。一般一两下之后就只剩真正的那几个。
3. **同步**：确定之后，每次回血时把这几个地址也改成新血量（写前比对旧值、写后读回确认、
   只写 `PAGE_READWRITE` 页）。以后挨打就不会再掉回去了。

## 为什么以前会卡
- 扫描 5 GB 内存本身就要时间：实测大约 **1.1 GB/秒**，全部扫完 **4.5~4.7 秒**。
- mod 运行在游戏的 Lua 更新回调里（Bingus Shared Loader 每帧调用一次 `update`），
  回调不返回，游戏这一帧就画不出来。一口气扫完 = 游戏卡住 4~5 秒。
- v0.12f 起每辆载具（机甲、坦克、FRV）各扫一次，所以一局里会卡好几下；
  部位数组对不上时还会重新扫（每次再卡 1~2 秒）。

## 现在怎么做的（v0.12g / v0.12h）
- **分帧扫描**：扫描放进 Lua 协程，每帧只扫一小段就把控制权还给游戏，下一帧接着扫。
  每一段是 1 MB，扫完一段检查一下这一帧已经用了多久。
- **按进度自动调节**（v0.12h）：
  - 目标是 `hunt_secs` 秒（默认 15 秒）扫完。
  - 进度跟得上时，每帧只用 `hunt_ms` 毫秒（默认 3 毫秒）；
  - 落后了（比如帧率低），每帧最多用到 `hunt_ms_max` 毫秒（默认 12 毫秒）。
  - 60 帧时每帧大约多花 5 毫秒，30 帧时大约 10 毫秒，基本感觉不到；一般 15~20 秒扫完。
- **一次只扫一辆**：多辆载具同时回血时排队，一辆扫完再扫下一辆。
- **扫描中挨打就作废**：扫的这十几秒里如果载具挨了打，游戏那份拷贝就变了，
  已经扫过的部分对不上，这次结果作废，下次回血重新扫（每辆最多 3 次）。

## 代价
- 扫描完成之前（大约 15~20 秒）挨的打，修的血照样会掉回去。
- 扫完之后的**第一下**伤害用来确认哪些地址是真的，这一下也会掉回去一次；之后就不再掉。
- 找到的地址只在这一局内存里有效，换局、载具重新呼叫都要重新扫一次（自动的，不卡）。
- 实在找不到时就放弃，这辆载具回退到老行为（修的血挨打后会掉回去），不会影响其他功能。

## 可调设置（`shield_resupply_settings.txt`）

| 设置 | 默认 | 说明 |
|---|---|---|
| `hunt` | 1 | 0 = 完全不扫描（不卡、但修的血挨打会掉回去） |
| `hunt_secs` | 15 | 目标扫描时长（秒）。调小扫得快，但每帧占用更多时间 |
| `hunt_ms` | 3 | 每帧至少扫多少毫秒 |
| `hunt_ms_max` | 12 | 落后于进度时每帧最多扫多少毫秒。觉得扫描期间掉帧就调小（例如 6），代价是扫得慢 |

日志里会看到 `hunt armed … 扫描 5222 MB 用时 x s（分 N 帧）`，
其中“用时”是从开始扫到扫完经过的时间（一般 15~20 秒），“分 N 帧”是拆成了多少帧。
