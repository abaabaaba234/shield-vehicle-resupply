# v0.25：速度恢复后仍跛行

用户更正此前观察：v0.24 已停止腿部火焰，移动速度正常，但走路动画仍一瘸一拐。此前的“移动正常”只确认速度，不能视为步态恢复。

## 当前两台 EXO-55 的实际差异

2026-10-01 17:02，同一局 PID 25540 只读核对：

| 参数 | 修过的机甲（实体 514） | 完好机甲（实体 608） |
|---|---|---|
| 主血量 | 1800/1800 | 1800/1800 |
| 八个部位 | 全满，包括两个 10 HP 区域 | 全满 |
| 损毁位 / 死亡状态 | 0 / 0 | 0 / 0 |
| StatModifier 移速倍率 | 1 | 1 |
| 前三个腿部动画节点 | 状态 3，左腿受损待机 | 状态 0，正常待机 |

两台使用同一动画定义，含 11 个节点、56 个事件。前三个节点的状态 3 均存在 `fine`（`bdf3a6a1`）到状态 0 的转换；状态 0 的 `limp_left` 又指回状态 3。受损行走状态 5 的 `fine` 返回正常行走状态 2，右腿受损也有相同的逆向转换。因此恢复步态需要动画事件；恢复移速和清除损毁位不会自动发出该事件。另一个原生路径使用 `exit_limp`，但本 EXO-55 动画定义没有该事件，不采用它。

## 实现

在护盾维修范围内、冷却结束、所有部位启用、机体与全部部位修满且存活有权威时，单独核对动画状态。沿完整 UnitReference 解析对象并验证代数、对象、控制器所属、网络／Health／动画组件描述符，以及 Unit API 函数指针。

有限读取动画定义的节点、状态、事件和转换表；只有当前状态的 `fine` 返回一个正常状态，且正常状态的 `limp_left` 或 `limp_right` 明确指回当前状态，才认定它是腿部跛行。正常动画不发送恢复事件。控制器与动画状态只读，未复制完好机甲的参数。

调用与原生腿部受损回调相同的 `game.dll+808810` 动画分发器，事件 `fine`、行为分发关闭、复制模式 1。调用仍由游戏内 Lua update 执行。分发器、左右腿回调、引擎 Unit 解析、事件接口和队列接口分别核对固定代码；校验失败只停用动画恢复，原有血量、移速、火焰和其他接口独立工作。

引擎异步处理动画事件，日志先记录 `exo gait event sent`，后续服务读到正常状态再记录 `exo gait state normal`；仍受损时至少等待 2 秒再重试。不能把 void 调用返回视为动画已恢复。

## 验证与限制

- 11 个离线测试脚本通过。新增回归重放当前 EXO-55 的完整动画定义及原生代码，覆盖左右腿、正常速度下的残留跛行、正常动画不触发、异步状态读回、行走状态保持、失败重试，以及身份／血量／状态在采样期间变化时拒绝调用。
- 使用实际新 Lua 读取逻辑对当前进程核对：修过的实体 514 通过全部校验，仅它成为 `fine` 事件候选；完好实体 608 返回 `no limp animation state`。该核对以 VM_READ 运行，替换了全部原生调用，未实际执行事件或写入游戏。
- 安装 v0.25 后，用户于 2026-10-01 确认“这次没有问题了”。17:11:31 游戏日志记录 EXO-55 实体 511 的移速从 0.75 恢复为 1，左右腿分别停止 `a1d3345e`／`4a3fa896` 火焰，发送 `fine`（三个受损动画节点）后读回 `exo gait state normal`；17:11:32 主血量 1800/1800、八个部位全部修满。本次实际步态恢复通过。
- 当前真实动画证据和游戏实测覆盖 EXO-55；其他机型必须通过自身动画定义的逆向转换检查。多人环境的事件复制尚需另测。

原始采样和脚本保存在研究目录的 `EXO55_limp_animation_v0.25_2026-10-01.zip`，包含只读核对结果。安装包为 `dist/ShieldVehicleResupply_v0.25.zip`；回血仍为原设定的 4%/秒。
