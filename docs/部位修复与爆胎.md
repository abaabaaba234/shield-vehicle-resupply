# v0.15 部位维修与爆胎恢复

参考用户下载的 `Vehicle-Supply-Tower-1.0.1/Addon/9ba626afa44a3aa3.patch_0` 中的
`mods/codex/vehicle_supply_tower` Lua 实现。它调用游戏维修函数与 `VehicleApi`；爆胎恢复不是
清除 `TagComponent` 的普通标签。filediver 的名称库虽含 `AbilityId_vehicle_*_wheel_dead`，
这些名字不等于可直接移除的 Tag 位掩码。

## 设置

```ini
heal=native
native_zone=0x141
part_regen=1
part_repair=1
tires=1
wheel_interval=2
```

更新 mod 包后重启游戏。上述设置也会成为新设置文件的默认值。`reload` 只重新读设置，
不能加载新的 Lua 包。

`part_repair=1` 在已毁部位或已毁状态位存在时调用维修无人机所使用的游戏函数。
每次的维修比例为车型每秒回血比例乘以服务间隔，最多 1；不是每次固定再加 5%。
主车体必须存活，运行时死亡字段必须为 0，本机必须有权威，并且载具在护盾范围内、
已过受伤冷却。维修函数会处理整车：任何有效部位被 `part=` 禁用时都跳过这个调用，
其余选中部位仍可走原生再生。`part_repair=0` 可单独关闭这条路径。

`tires=1` 使用 VehicleApi，而非直接改 Health 数值和损坏位：

1. 在护盾外也会只读观察本机有权威且存活的 FRV，记录各接口编号的完好 48 字节参数。
2. 同一车型的样本可以用于另一辆同型车；按接口编号分别缓存，不拿左轮参数填右轮。
3. 进入护盾并结束受伤冷却后，每辆车至多每两秒恢复一个爆胎。
4. 调用 setter 前再次确认实体/句柄，随后用 getter 确认爆胎标志已清零。

如果加载 mod 时同型号所有车的同一个轮胎已经爆了，就没有该位置的完好样本。
这时召唤一辆轮胎完好的同型 FRV，等至少一次观察更新；它不需要进护盾。
切换任务或主世界会清空缓存。

## 独立开关与轮胎编号

`part=<资源hash>:<部位hash>=0|1`、`part_regen` 仍独立控制部位。
FRV 已知血量部位为：

| 部位 | Health hash |
|---|---|
| 前左 | `fed0a478` |
| 前右 | `f3cb00ad` |
| 后左 | `c6bf05a9` |
| 后右 | `f12186b7` |

**VehicleApi 的轮胎编号不能直接使用 Health 部位索引。**
当某次观察只有一个新损坏血量部位、只有一个新爆胎接口标志时，脚本记录两者的对应。
多人同步或多个轮胎一起坏导致观察不明确时不会猜。默认四轮全选时可恢复任意轮胎，
无需知道它的 Health 名称；仅选择部分轮胎时只修复对应关系已确认且选中的接口编号。
为确认关系，可以在轮胎完好、mod 已运行时逐个打爆，每次等待至少一次服务更新。
相互矛盾的观察会清空对应表。

## 日志和验证

- `repair native health: ok`、`repair native wheels: ok`：新接口的字节与布局检查通过。
- `native zone ... offset=+141: on=35/35 blocked=0`：该 FRV 的部位再生已成功打开。
- `wheel learned ... index=...`：缓存了该接口编号的完好轮胎参数。
- `part repair ... game repair function`：调用了游戏维修函数。
- `wheel repaired ... flag=1->0`：setter 后读回爆胎标志已清零。
- `wheel mapping learned ... api_index=... zone=...`：观察到单轮损坏并确认了编号对应。
- `wheel repair skip ... no intact tyre sample`：还缺完好样本；召唤同型号完好车。
- `wheel mapping skip` / `repair native ... guard`：接口或实体校验失败，相关调用跳过。

发 `parts` 可看 HP、再生、损坏位、死亡动画事件、回血脚本事件与 actor 标志。
护盾服务时也会自动记录四轮 HP/状态变化。

参考 mod 明确说明轮胎恢复移动能力与爆胎标志，**不处理模型**。本版本也不重建轮胎
外观或已移除的独立手臂。车门、手臂、炮塔等的最终模型、碰撞与功能是否恢复，
需要在当前游戏中分别验证；维修函数参考注释不构成本 mod 的游戏实测。

## 验证范围

`tests/repair_native_test.py` 使用实际打包的 LuaJIT 脚本、模拟原生调用和内存，验证
接口检查、48 字节恢复、setter 读回、权威/死亡/句柄检查、缓存、不同索引对应、
模糊观察跳过、独立禁用、冷却和没有护盾时不发生维修写入。
`tests/part_regen_test.py` 另外使用 filediver 原始 FRV 配置，验证 35 个部位全部通过，
ChildZones/枚举不被误写，离开后精确恢复原值。测试不模拟真实游戏物理或模型。
